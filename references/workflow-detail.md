# 各闸门操作细则

## Gate 1 作者资格核对细则

### 收集信息
信息不全先问齐再判，不猜、不脑补。需要：姓名、单位全称（含城市邮编）、职称/职务、学历、研究方向、电话、邮箱、在投状态（现有稿件投了哪些刊）。

### 四项核对

| # | 核对项 | 判定标准 | 不过的处理 |
|---|---|---|---|
| 1 | 真实性 | 单位真实可查；虚构单位、代写、挂名请求一律拒绝 | 学术真实性红线，不可谈判，直接终止 |
| 2 | 一稿多投 | 同稿已在其他期刊在投 → 不过 | 终止；撤稿后方可重新走流程 |
| 3 | 同刊多稿 | 该作者目标刊已有 1 篇在投 → 可继续，但成稿后必跑重叠扫描、投稿错开数天；已有 2 篇及以上 → 建议等初审结果，暂缓 | 暂缓，不是终止 |
| 4 | 题材适配 | 作者有实务背景能撑起该刊偏好的写法 → 适合；背景只能写成该刊明确不收的类型 → 不适合 | 让作者确认能否提供适配素材，不能则终止 |

### 判定执行
- 适合 → 逐项报 ✓，进 Gate 2。
- 不适合 → 明确告知"当前不适合投稿《X刊》"，逐项列未通过项与原因，立即终止。最多一句补救路径（如"撤回在投稿件后可重新走此流程"），然后停止。不收集题目、不写作、不进 Gate 2。

## Gate 2 期刊调研细则

### 2.1 找官方投稿须知
- 路径：期刊官网"投稿指南/稿约/作者须知"、官方公众号历史消息。
- 防冒牌：确认官网真实性（备案信息、知网/万方期刊导航页给出的官网链接）。有≥2 个冒牌站的期刊（本技能已知《大都市》属此类），以数据库标注为准。
- 提取字段（缺一标记"须知未载明，需向编辑部确认"）：栏目清单、字数区间、查重率上限、格式模板、参考文献规范、必备项、审稿周期、是否收费、投稿渠道（在线系统/邮箱）、匿名要求（不匿名/单盲/双盲，未载明需向编辑部确认）。
- **来源甄别，防"串刊"**：第三方聚合站转载的稿约可能混入同名刊、前身刊或更名前的旧须知。核对**落款日期 vs 本刊创刊时间**、主办单位、CN/ISSN；时间对不上的规则一律不得套用。血案：2026-11-18 作者提供的截图里混进 2020 年《铁路工务》征稿须知，而目标刊《铁道工务》2023 年 10 月才创刊，是两本刊；旧刊"5000–6000字"等规则差点被当成现行要求。
- **第三方站点数据不可尽信**：多个聚合站对同一刊的字数、摘要、关键词数量常互相矛盾（套模板所致）。只有"原创、不抄袭、不一稿多投"这类共识可用；具体数字以官网/编辑部答复为准。
- **未载明项的处理**：官方无明确规定时（如查重率上限），清单里标"需向编辑部确认"并给出电话/邮箱，可附行业保守经验值，但**必须明确区分"该刊规定"与"通用经验"**，不得把经验值写成刊方要求。
- **避开作者声明被封禁的域名**：若作者告知某站曾导致其 IP 被封，不访问该站，只读作者提供的截图，并在报告中注明来源。

### 2.2 抓目录与摘要
- 来源优先级：期刊官网过刊浏览 > 知网/万方检索结果页（题录+摘要，通常公开） > 官方公众号推文 > 龙源期刊网目录页（qikan.com.cn，常能列出完整栏目+期次）。
- 范围：近 1–2 年，覆盖全部栏目，**且必须跨至少 3 个不同期次**。
- 多源交叉：某平台过刊接口失效（如 CNKI 只回引文格式）时，改用龙源期刊网、维普、知网阅读页、被引/下载排行页补齐期次，**不得因一个接口失败就缩样本**。
- 输出"选题地图"：高频主题词、各栏目占比、标题字数与句式分布、是否有热点跟随。

### 2.3 样本充分性硬规则（2026-11-18 踩坑固化）
- **禁止基于单一期样本下"命中率极低/该刊不收X类"这类强结论**。单期只反映该期组稿情况，不代表全年。
- 下题材适配判断前，硬门槛：目录样本 ≥ 3 个不同期次，且尽量涵盖不同栏目。
- 样本不足时只能表述为"目前所见 N 期未见 X 类，是否收录待核实"，并继续抓取，不得写成定论。
- 血案：2026-11-18《铁道工务》仅据 2026 年 04 期 6 篇实证文章，就断言"综述/纯理论 0 篇、无数据必死、命中率极低"；补查 2025 年多期后发现大量理论框架（PDCA 安全风险研判）、仿真（ABAQUS、SegFormer）、现状构想（轨道作业车发展构想）、管理实践（人才培养"1+N"）等**不需一手现场数据**的文章。结论被完全推翻，白吓作者一次。
- 教训核心：**期刊某一期的组稿倾向 ≠ 该刊的收录边界**。栏目设置（尤其"工务综合""技术园地"等综合栏目）才是判断某类题材能否投的更可靠依据。


### 2.4 能力边界与代下载（如实说，不编造）
- 可代做：联网找官方通知、抓目录与摘要、生成下载清单；**本机装有"川图文献下载"技能时，正文 PDF 可由 agent 代下载**（四川省图书馆共享平台→知网镜像，合法通道，不涉及作者账号密码）。
- 不可代做：接收/输入账号密码、读 CAJ 或纯扫描 PDF、绕过任何付费墙。
- 川图技能可用性检查：`C:\Users\user\.zcode\skills\journal-submit\川图文献下载\SKILL.md` 存在即可用；代下载操作细节（受控 Edge 启动、登录检查、代理域名映射、Referer 下载、PDF 校验）以其自身 SKILL.md 为准，本技能不重复维护。
- 代下载执行规则：
  1. 按模板 C 清单逐篇下载，PDF 存本任务工作目录（如 `范文/`），不写入川图技能自带的"已下载"目录；
  2. 每篇校验（PDF 头 + 页数 + 首页题名比对）后回写清单状态（✅已得 / ❌原因）；
  3. 失败回落顺序：知网镜像无 → 万方 → 维普；仅 CAJ/扫描版 → 交作者转 PDF 或截图；平台未登录/滑块验证 → 请作者在受控 Edge 窗口手动操作一次后重试；
  4. 川图技能不可用 → 回到作者手动下载：交模板 C 清单 + 每篇提取说明。
- 红线不变：代下载只换"跑腿的人"，正文须有文字层才能进 Gate 3；不编造未见到的内容。

## Gate 3 范文拆解细则

- 数量：精读 5–8 篇同栏目近两年文章；泛读 15–20 篇标题与摘要。
- 每篇按 `templates.md` 的六维拆解表填一遍，**版式与体例速查（模板 D2）必填**，填完归纳跨篇规律。
- 版权红线：拆解只记录"规律"（如"标题多为 12–18 字陈述句""每篇 3 个一级标题"），不摘录原句原文；引用观点必须标注出处。
- **结论体例、摘要体例、表格线型、引号形式、著录细节、作者简介写法**必须在这一步显式记录，不能留到成稿后靠回翻范文确认——这些是编辑初审最先看的格式特征。

## Gate 4 题目确认细则

- 基于偏好报告给 3–5 个选题，每个附"依据哪条范文规律"。
- 预检四项：字数符合该刊要求、导向落在目标栏目口味、不与近两年已发题目高度重复、不含该刊禁用的表达（如外文字母缩写需按须知判断）。
- 作者点头才进 Gate 5。

## Gate 5 成稿细则

- 先出详细提纲（章节、每章要点、数据锚点位置、案例锚点位置），作者确认后再写。
- 初稿按偏好报告设定的结构骨架写：数据锚点数量、案例锚点数量、文献数量与可查性。
- 润色阶段对齐该刊文风，检查 Gate 3 归纳的所有规律是否命中（含模板 D2 的版式与体例）。
- **写作全程单线程**，避免多执行体拼接导致风格割裂。

### Gate 5 补充规则：无实测数据稿件（作者常见处境，必读）

作者明确"只有文献、无数据"时，文章仍可写（理论框架/管理方法/现状构想/仿真类），但必须守住：

1. **不得编造任何量化结果**：百分比、样本数、"下降 X%"、"覆盖 N 个"一律不写。
2. **不得写效果断言**："未发生责任事故""显著提升""有效遏制""明显增强"等，改为机制性表述（"为…提供了机制保障/闭环载体/制度基础"）。
3. **摘要不得超出正文证据**：摘要每个结论都要能在正文找到支撑段落；找不到就删断言，**绝不能反过来往正文补一句"事实"来圆摘要**——那是编造。
4. **应用/效果章写法定性化**：用"管理理念由A转向B""重心前移""形成闭环机制"这类结构性变化描述；明示"台账尚在完善、量化统计有待后续"，并在结论中把量化验证列为下一步工作。
5. **不代填作者未提供的事实**：职称具体名称、邮箱、实测值等，标注"待作者确认"，不擅自编造；作者明确表示不补的，保持原状并在交付说明中记录。

### Gate 5 补充规则：匿名稿处理（按 Gate 2 硬指标清单的匿名要求执行）

1. **不匿名刊**：按须知附作者简介、单位、电话、地址（如《轨道交通装备与技术》刊内启事明确要求）。
2. **单盲刊**：作者信息保留，正文内不出现"本文作者曾…"类自我指涉。
3. **双盲刊**：正文与文件属性删除作者/单位/简介/联系方式/致谢中的身份线索；基金号若可定位作者须删或脱敏；作者信息与单位声明整理为单独一页，不并入正文；自引规避第三人称（"文献[x]提出"而非"我们先前提出"）。文件属性检查：docx 元数据（作者字段）也要清理。
4. **匿名要求判定树（先判断、只出一版；禁止默认产出两版）**：
   - ① 须知明示双盲/匿名审稿 → 只出一版匿名稿；作者简介/单位/电话/地址整理为**单独一页**随稿另附，不并入正文；
   - ①-b 须知明示**"实名版+匿名版两个 word 文档同时投稿"**（例：《机车车辆工艺》投稿须知第(2)条，用于盲审）→ 按须知交付**两份文件**：实名版保留全部作者要素；匿名版删除姓名/单位/电话/邮箱/地址及英文部分作者信息，正文不出现"我校/本团队"、基金、致谢等可推身份内容，交付前**程序核验零残留 + 清理 docx 文件属性（作者/公司字段）**；两份同时投稿；
   - ② 须知明示需附作者简介/联系方式（即非匿名）→ 只出一版非匿名稿；
   - ③ 须知未载明 → 依次查：期刊采编系统投稿页有无盲审提示 → 官方公众号投稿指引 → 仍无则**默认非匿名，只出一版**（国内科技期刊以非匿名/单盲为主；若编辑部初审后要求盲审，按第 3 条补脱敏版，成本很低），并在交付说明注明判断依据。
   - **范文不能用于判断审稿匿名性**：已发表论文必然署名（刊出形态），不反推审稿形态；匿名性只依据须知/采编系统/编辑部答复。
   - 同时交付匿名版+非匿名版属于**交付缺陷**：作者不知道发哪份；给非匿名刊的匿名版会因缺作者信息被退回。

### Gate 5 补充规则：全文级改稿走源头脚本

- 若初稿由脚本生成（含上标引用、三线表、内嵌图等复杂 XML 格式），**多轮全文修订一律改生成脚本后重新生成 docx**，不要逐处编辑成品——直接改 docx 容易破坏上标、边框与图片关系。
- 重新生成后必须重跑：占位符零残留、上标数量、表格数、图片数、引号配对、格式自检。
- **作者打开着文件时要先请其关闭**，否则写入可能被占用；交付前用文件修改时间 + 修改点抽查双重确认改动已落盘。

## Gate 7 投稿与跟踪细则

- 按官方渠道投（在线系统或邮箱），题目按系统要求填（可能需要精简版，提前备好）。
- 记录：投稿日期、审稿周期节点、稿件版本号与 md5。
- 到节点无回音 → 按须知允许的时点礼貌询问。
- 收到任何反馈（退稿/录用/修改意见）→ 回写画像，更新偏好报告与阈值，注明日期与案例。
