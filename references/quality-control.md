# 质检链与降 AIGC 分支（Gate 6）

## 质检顺序（全绿才交付）

1. **格式自检脚本**：`python scripts/audit_loop.py <稿件.docx> --must-contain "锚点词1,锚点词2"`
   - 参数按稿调整：`--refs-min/--refs-max`（文献数）、`--chars-min/--chars-max`（字数）、`--min-cites`（最少引用）、`--must-contain`（该稿专属必含词：城市锚点、作者要素等）。
   - 退出码 0=全 PASS，1=有问题，2=文件/参数错误。
   - **工具会误报**：协议名≠英文缩写、文献条目编号≠漏上标。见红先甄别真伪，不许见红就动稿。
   - **上标双向规则（2026-11-23 踩坑固化）**：正文引用标注 `[n]` 必须是 XML 真上标；**文末文献表的序号 `[n]` 必须为非上标**（GB/T 7714 的条目标号，不是引用标注）。血案：生成脚本的 `add_para` 用同一逻辑处理正文与文献表，无差别把所有 `[n]` 转成上标，18 条文献序号全被误转；而 R7 按规则故意跳过文献区，导致格式自检全 PASS 却带错交付，最后靠作者肉眼发现。**已加 R14 自动检查此盲区，脚本生成稿件必跑。**
2. **引用双向对应**：正文 [n] 与文末文献表一一对应、编号连续、无漏引无虚引。
   - **脚本生成类必查残留标记**（2026-11-18 踩坑）：若正文由脚本用占位符（如 `{{1-2}}`）生成上标，交付前必须扫描成品 docx 文本，确认占位符零残留，并核对上标总数与原文引用数一致。血案：正则只支持 `{{n}}` 不支持 `{{1-2}}` 范围写法，导致 4 处标记原样印进成品，格式自检脚本因不检查占位符而全部 PASS，险些交付带乱码标记的稿子。**规则：占位符解析的正则必须覆盖范围写法 `[-,]`，且成品要独立做一次"无占位符残留"断言，不能只依赖格式自检。**
3. **查重自测**：作者用常用平台（如 paperyy 等）自测，对照该刊上限；红句回传后逐句定点改写，**数据、结论、引用序列一字不动**。
4. **AI 率诊断**：作者有降 AI 需求、或检测超标、或投稿须知要求 AIGC 达标时 → 走下方分支。作者没提且未超标 → 不主动推销，交付时提一句"可自测"即可。
5. **渲染层校验**（有 LibreOffice + pdfplumber 时）：docx 转 PDF 后查文字坐标无越界；表格跨页时表头重复、行不断开；引用上标为 XML 真上标（w:vertAlign），文献表序号为非上标（R14）。
6. **段落对齐核对**（对齐无统一国标，按该刊范文/作者定）：核对标题、作者、单位、图题、表题、表格是否居中，正文是否两端对齐。血案（2026-11-23）：脚本默认 `align=None` 导致正文为左对齐、且未设表格单元格居中，作者在 Word 手工调整后才符合刊例。**脚本生成时应显式指定对齐，不要依赖默认值**：题名/作者/单位/图表题居中，正文两端对齐（WD_ALIGN_PARAGRAPH.JUSTIFY），表格按刊例居中。

## 内容一致性通读（独立于格式自检，必做）

**血案（2026-11-18 实测固化）**：一篇经脚本生成、格式自检"全部 PASS、零问题"的稿件，外部视角通读全文后一次揪出 3 处硬伤级前后不一致、4 处语病、6 处用词口径问题；随后主笔再独立通读一轮，又补出 5 处外部审查漏掉的问题（术语不统一、行业事实不准、效果断言超证据等）。**结论：格式脚本查"符不符合排版规则"，查不了"文章自己说得通不通"。这一层必须单独做，且不能只做一轮。**

### 必查清单（逐项过，逐项给证据）

| # | 检查项 | 具体做法 | 典型病例 |
|---|---|---|---|
| 1 | **数量词 ↔ 实际项数** | 全文出现"N 个维度/阶段/步骤/方面/件套"处，逐一数清后文列举项、表格行数、图数、结论分条数是否=N | 正文"四个维度"但对比表实际 5 行 |
| 2 | **摘要断言有正文支撑** | 摘要每一句结论，回正文找对应段落；找不到 → 删或降级为定性表述 | 摘要"未发生责任事故"，正文却声明"台账待完善、定性分析" |
| 3 | **核心口径全文统一** | 抽取文章自创的核心工具/框架名（如"三件套""四阶段"），全文检索是否冒出无归属的同类命名 | 摘要/结论是"一清单、一矩阵、一台账"，正文却多出"一表" |
| 4 | **术语统一** | 建核心术语表，全文扫描别名混用（尤其同义动词、专业名词） | "风险辨识"与"风险识别"混用 |
| 5 | **同一表述口径统一** | 同一现象在不同章节的叫法要一致，含图题/表题/表格单元格 | 3.2"重结果、轻过程" vs 1.2 与表4"重前后、轻过程" |
| 6 | **名称统一** | 清单名、表题、图题与正文引用它的叫法一致 | 摘要叫"实训安全风险源辨识清单"，表题叫"…主要风险源辨识清单" |
| 7 | **行业事实准确性** | 专业名称、设备/构件名、规范号、机构名逐项核，别让 AI 按字面拼 | 工务实训基地的服务专业写成偏运输/机车的专业；构件"飞溅"应为"弹飞" |
| 8 | **结论强度 ↔ 证据强度** | 无实测数据稿，凡"有效遏制/显著提升/未发生X"等效果断言一律降级为机制性表述（"为…提供了机制保障"） | 全文声明无量化统计，却写"同类问题得到有效遏制" |
| 9 | **匿名合规** | 按硬指标清单"匿名要求"核对成品：不匿名→作者信息齐全；单盲→无自我指涉；双盲→正文与文件属性零身份线索、作者信息另页 | 双盲刊稿内残留"作者简介：××（××大学）"，直接暴露身份 |

### 两轮视角规则

- **第一轮：外部/独立视角**（另一个执行体、另一份审查意见、或作者本人通读），只指出不动稿。
- **第二轮：主笔逐条核实后再独立通读一轮**。外部意见**先核实真伪再采纳**，不照单全收——误报和不合用的改法会污染稿件（例：审查建议"在正文补一句未发生事故"以支撑摘要，但作者无台账数据，补了就是编造；正确解法是删摘要断言）。
- 实测两轮互补：第一轮抓"前后不一致"，第二轮抓"术语/事实/断言强度"。**只做一轮会漏。**

### 交付前断言

- [ ] 正文引用 `[n]` 全部为真上标，文献表序号 `[n]` 全部为非上标（R7+R14 双向核对）
- [ ] 段落对齐符合刊例：标题/作者/单位/图表题居中，正文两端对齐，表格按刊例居中
- [ ] 数量词全部与实际项数对齐
- [ ] 摘要无超出正文的断言
- [ ] 核心口径、术语、名称、同一表述全文一致
- [ ] 无实测数据处无效果断言与量化结论
- [ ] 匿名合规：按硬指标清单的匿名要求核对成品稿（不匿名→作者信息齐全；双盲→正文/文件属性零身份线索）
- [ ] 两轮视角都跑过，且每条外部意见都标注了"采纳/不采纳+理由"

## 降 AIGC 分支

### 第 0 步 版本鉴定（读数字前必做）
血案：作者回传的检测报告实测的是改写前旧稿，19.5% 是旧稿成绩，新版实际 0 命中。
做法：取报告红句特征串，与**当前版**比对；旧版命中而当前版 0 命中 = 报告评的不是这版 → 数字作废，请作者用当前版重测，不基于废数字改稿。**解读任何外部评估数字前，先鉴定它评的是哪一版。**

### 第 1 轮 指纹词清除（本地）
清除 AI 高频 fingerprint 词、"A 的 B 与 C"结构、解释型破折号、三段式套话（首先…其次…、值得注意的是、综上所述）。学术语护栏不撤：hedging 学术化转换≠口语化，不引入情绪标点、不模糊数字。

### 第 2 轮 红句定点清除（作者自测后）
红句逐句改写；改完可再测一轮。事实、数据、统计量、引用序列保持零漂移。

### 两条不可谈判的红线
1. **事实保真一票否决**：数据、结论、统计量、引用序列一字不动。零漂移复验：表格内容/数据锚点数/引用序列与改前逐项 diff，零漂移才交付。
2. **草稿不外发**：任何要求上传全文到外部降 AI 管线的做法一律拒绝，本地方法等效。改写全在本地完成。
