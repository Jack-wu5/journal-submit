# 多智能体协作策略

## 结论先行

**分阶段用，不是全程用。** 一句话原则：一个统一的大脑写，多个独立视角审。

## 分阶段编排表

| 阶段 | 是否用多智能体 | 理由 |
|---|---|---|
| Gate 2 抓目录/摘要、建清单 | 建议 | 多篇、多源信息并行收集，互不干扰 |
| Gate 3 范文拆解 | 建议 | 每篇范文一个子任务并行拆，或按维度（选题/文风/结构）分工，最后汇总 |
| Gate 4 定选题 | 可用 | 几个子任务从不同角度发散选题，作者挑；但汇总需单一执行体 |
| Gate 5 写初稿与润色 | **不建议** | 核心创作需统一声音与连贯思路，拆给多个执行体会风格割裂、前后矛盾 |
| Gate 6 打磨与挑错 | 建议 | 不同角色并行审：编辑看选题命中率、审稿人挑逻辑漏洞、文字校对润色——视角互补 |
| Gate 7 格式化自检 | 无所谓 | 机械活，单线程更稳 |

理想模式：信息收集并行 → 主笔单点写作 → 评审并行 → 单点收尾。

## 编排要点

- 子任务之间要传上下文，信息有损耗；给每个子任务写清楚"输入是什么、输出什么格式"，别让它猜。
- 汇总环节必须由单一执行体完成，负责去重、消矛盾、统一口径。
- 拆分粒度：按"可独立验证的产物"拆（一篇范文的拆解表、一个视角的审稿意见），不按"写作段落"拆。
- 成本意识：链路越长细节损耗越多。一篇普通期刊稿，多数情况下"单主笔 + 一轮并行评审"就够，不必全程铺开。

## 评审意见的处理规则（2026-11-18 实测固化）

- **外部意见先逐条核实，再决定采纳**：不要因为对方写得笃定就照单全收。核实方式＝打开文档/范文找原文证据，逐条标"属实/误报/部分成立"。误报和不合用的改法会污染稿件。
  - 实测病例：外部审查建议"在正文补一句未发生事故"来支撑摘要断言，但作者无台账数据，补了即编造 → 正确解法是删摘要断言。审查建议"把核心工具扩成四件套"也不如"去掉多余命名"干净。
- **采纳之后，主笔必须再独立通读一轮**：外部视角会漏。实测中第一轮（外部通读）抓的是"前后不一致/口径分裂"，第二轮（主笔自查）抓的是"术语不统一/行业事实不准/效果断言超证据/PDCA 英文写法"，**两轮互不覆盖**。
- 顺序：外部只指出不动稿 → 主笔给"采纳/不采纳+理由"的判断 → 执行修改 → 主笔再独立通读 → 逐项校验。
- 这类"审查—核实—修改—复核"不要求多个子智能体同时在线；串行两个不同视角同样有效，关键是**视角不同**且**至少两轮**。
